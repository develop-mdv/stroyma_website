## Резервные копии

Ежедневный бэкап PostgreSQL и `media/` запускается systemd-таймером `stroyma-backup.timer` около 03:00–03:05 по Москве. Пары файлов лежат в `backups/` с правами `600`, срок хранения на сервере — около 14 дней. Очистка истёкших сессий запускается по воскресеньям в 04:00 через `stroyma-sessions.timer`.

Первая пара: `pg_20260930_195101.sql.gz` и `media_20260930_195101.tgz`. Восстановление дампа проверено в отдельной временной базе: 140 товаров, 48 категорий, один новый администратор и 0 заказов. Временная проверочная база удалена после проверки. Первая пара также скопирована на локальный компьютер в `backups/deploy-20260930/`. Автоматическая отправка последующих копий во внешнее хранилище не настроена: для неё потребуется выбранное владельцем хранилище и доступ.

```bash
cd /opt/stroyma/stroyma_website
docker compose ps
docker compose logs --tail=100 web worker caddy
systemctl list-timers stroyma-backup.timer stroyma-sessions.timer
journalctl -u stroyma-backup.service --no-pager -n 50
```

Для обновления сначала выполнить `bash deploy/backup.sh`, передать новую версию кода в папку приложения, сохранив серверные `.env`, `docker-compose.server.yml`, `media/`, `logs/`, `staticfiles/` и `backups/`, затем:

```bash
cd /opt/stroyma/stroyma_website
docker compose build web
docker compose up -d
docker compose exec -T web python manage.py check --deploy
```

Не использовать `docker compose down -v`: тома содержат рабочую базу и данные сертификата. Для восстановления использовать последовательность из `deploy/DEPLOY_VPS.md`; основную версию PostgreSQL сохранять 17 до отдельной миграции кластера.

## Почта: SMTP проверен после открытия порта

При первичной выкладке подключения с VPS к SMTP Яндекса на портах 465 и 587 завершались тайм-аутом. Владелец разблокировал порты в панели провайдера и сообщил об этом 30.09.2026. После открытия порта 465 из работающего Django-приложения успешно выполнены подключение к `smtp.yandex.ru:465`, SMTP-аутентификация с серверными настройками и команда NOOP. Соединение использует TLS 1.3 с проверкой сертификата. Менять SMTP-настройки или перезапускать приложение не потребовалось.

Worker уведомлений работает; на момент повторной проверки ожидающих и ранее отправленных уведомлений было 0. Тестовые письма в рамках проверки не отправлялись, доставка в почтовый ящик отдельно не проверена. Приложение настроено на SMTP для уведомлений, подтверждения адреса и восстановления пароля; заказы сохраняются в БД, worker повторяет уведомления при ошибке SMTP.

Несмотря на снятие ограничений в панели провайдера, UFW на самом VPS остаётся активным: входящие соединения по умолчанию запрещены, публично разрешены SSH, HTTP/HTTPS и мониторинг с IP провайдера. Порты PostgreSQL 5432, Redis 6379 и Gunicorn 8000 не опубликованы на хост; повторная проверка с внешнего компьютера не обнаружила доступа к ним. Порт 5060 сайт не использует.

DNS: A-запись проверена и указывает на VPS. AAAA-запись на момент проверки отсутствовала; глобального IPv6 у сервера не обнаружено.
